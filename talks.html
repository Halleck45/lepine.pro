Je donne des conférences depuis 2012, principalement dans la communauté PHP francophone : Forum PHP, PHP Tour, AFUP Day et divers meetups. Les sujets tournent autour de la qualité logicielle, de l'analyse statique et de l'architecture. Cette page rassemble les vidéos et les supports encore en ligne.

J'ai analysé 236 Go de code PHP : état des lieux d'un écosystème

J'ai téléchargé l'ensemble des dépôts Git open source PHP disponibles (236 Go) et fait tourner des outils d'analyse dessus. Le talk présente ce qu'on y trouve : adoption des fonctionnalités récentes du langage, longueur des méthodes, dette, écarts entre frameworks, et les limites de l'exercice.

PHP, sans PHP : créez des binaires autonomes de votre code

Compiler un script ou une bibliothèque PHP en binaire statique, exécutable sur une machine où PHP n'est pas installé. Ce que ça permet, ce que ça ne permet pas (extensions, compatibilité), et dans quels cas c'est une alternative raisonnable à Bash, Python ou Go.

Faut-il faire du travail de qualité ?

Bob estime un site à une semaine, sans tests ni outillage. Alice l'estime à huit semaines, avec Docker, Jenkins et PHPUnit. Le talk part de cette histoire pour discuter de ce qu'on appelle qualité et de ce qu'elle coûte.

L'analyse statique coûte peu et s'installe vite, mais ses métriques sont souvent mal lues. Comment elles sont calculées, ce qu'elles indiquent sur un projet, et comment les utiliser au quotidien.

Sujets disponibles

Si vous organisez un événement.

Les sujets que je peux présenter en ce moment. La durée et le niveau s'adaptent au format et au public.

01
Métriques de code : lecture et pièges

Complexité cyclomatique, maintenabilité, couplage, instabilité : comment elles sont calculées et ce qu'on peut en conclure. Démonstration avec PhpMetrics et AST-Metrics.

02
État des lieux de l'écosystème PHP open source

Résultats de l'analyse de l'ensemble des dépôts open source PHP : fonctionnalités du langage réellement utilisées, dette, écarts entre frameworks, effet du code généré par IA.

03
Moderniser une base legacy sans la réécrire

Architecture hexagonale, DDD et déploiement continu introduits progressivement dans une application existante. Retour d'expérience sur deux ans.

04
Plan de continuité après un incident majeur

Ce que nous avons mis en place après avoir perdu la moitié de notre production : documentation, automatisation, exercices de reprise.

05
PHP en ligne de commande et en binaire statique

Compilation de PHP en exécutables autonomes, outils CLI distribuables, parsing de code PHP depuis Go.
